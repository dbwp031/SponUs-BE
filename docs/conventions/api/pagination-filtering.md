# 페이지네이션과 필터

상태: Draft

## 목적

목록 API의 페이지, 정렬, 다중 검색 조건 표현을 통일하고 데이터 증가 후에도 안정적인 결과를 제공한다.

## 페이지 요청

```http
GET /api/v1/announcements?page=0&size=20
```

- `page`는 0부터 시작한다.
- 기본 `size`는 20이다.
- 최대 `size`는 100이다.
- 음수 page, 0 이하 size, 최대 크기 초과는 `400`으로 처리하거나 최대값으로 보정하지 않고 명시적으로 거절하는 것을 제안한다.

## 페이지 응답

```json
{
  "items": [],
  "page": 0,
  "size": 20,
  "totalElements": 0,
  "totalPages": 0,
  "hasNext": false
}
```

- Spring Data `Page`를 직접 직렬화하지 않는다.
- Dashboard의 최근 N개처럼 고정된 소량 조회는 페이지네이션을 적용하지 않는다.

## 기본 정렬

```text
createdAt DESC, id DESC
```

- 동일한 `createdAt` 값에서도 결과 순서가 안정적이도록 ID를 보조 정렬 키로 사용한다.
- 클라이언트가 Entity 필드명을 임의로 sort 값에 넣게 하지 않는다.
- 추가 정렬이 필요하면 `LATEST`, `DEADLINE_ASC`처럼 허용된 enum 계약으로 제공한다.

## 다중 필터

같은 파라미터를 반복하여 복수 값을 전달한다.

```http
GET /api/v1/announcements
    ?regions=SEOUL
    &regions=GYEONGGI
    &clubCategories=PERFORMANCE
    &clubCategories=SPORTS
    &memberCount=50
    &page=0
    &size=20
```

결합 규칙:

- 같은 필터 종류의 값은 `OR`다.
- 서로 다른 필터 종류는 `AND`다.
- 파라미터를 보내지 않으면 해당 필터를 적용하지 않는다.
- 잘못된 enum 값은 `400 E0001`이다.
- 문자열로 받은 숫자와 날짜의 변환 실패도 `400`이다.

위 예시는 다음 의미다.

```text
(서울 OR 경기)
AND (공연 OR 체육)
AND 회원 수 50명 조건
```

## SponUs 모집 조건

- 공고의 지역 목록이 비어 있으면 모든 지역을 허용한다.
- 동아리 분야 목록이 비어 있으면 모든 분야를 허용한다.
- 회원 수 조건이 비어 있으면 모든 규모를 허용한다.
- 모집 조건과 동아리 정보가 일치하지 않아도 지원을 차단하지 않는다.
- 검색 결과와 지원 가능 여부를 동일한 규칙으로 오해하지 않는다.

## 검색어

검색어가 추가될 경우 다음을 명세한다.

- 검색 대상 필드
- 앞뒤 공백 제거 여부
- 대소문자 구분 여부
- 부분 일치 여부
- 최소·최대 길이
- DB 인덱스와 검색 성능 기준

현재 검색어 상세 규칙은 미결정이다.

## 금지 사항

- 쉼표 문자열을 임의 분리하는 다중 필터
- Entity 필드명을 그대로 받는 범용 정렬
- 정렬 없이 offset 페이지네이션 사용
- 빈 목록을 `404`로 반환
- 검색 조건 불일치만으로 지원 Command 거절

## 테스트 기준

- 같은 조건의 OR와 조건 종류 간 AND를 각각 검증한다.
- 조건 생략, 빈 결과, 잘못된 enum을 검증한다.
- 동일 생성 시각 데이터에서도 페이지 중복·누락이 없는지 검증한다.
- size 상한을 검증한다.

## 미결정 사항

- 허용할 추가 정렬 enum
- 자유 검색어의 대상 필드와 검색 방식
- 목록 규모 증가 시 cursor pagination 전환 기준
